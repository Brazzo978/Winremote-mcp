# Problemi comuni

Prima di diagnosticare il bridge, verifica che **lo stesso EXE aggiornato** sia presente sul PC controllato e sul PC dell'agente. Per QR e approvazione locale serve il sorgente 0.6.0 compilato su entrambi; la release scaricabile 0.5.1 non include queste funzioni. Riavvia il processo MCP dopo l'aggiornamento per caricare il nuovo catalogo. Tieni aperta la console del bridge e usa un invito generato dall'avvio corrente. Per la configurazione iniziale vedi la [guida rapida](getting-started.md).

| Sintomo | Controllo e rimedio |
|---|---|
| Codex non mostra gli strumenti winremote | Sul PC dell'agente verifica il percorso assoluto dell'EXE in ~/.codex/config.toml, la tabella [mcp_servers.winremote], enabled = true e gli argomenti mcp --connection. Riavvia o riconnetti il server MCP. Con Codex CLI, usa codex mcp list. Conserva le altre sezioni del file di configurazione. |
| bridge_connect fallisce o la connessione risulta scaduta | Ricopia l'invito dall'avvio corrente del PC controllato, senza spazi. La sessione predefinita dura un'ora; chiusura della console e nuovo avvio invalidano l'invito precedente. Controlla che il PC dell'agente raggiunga l'IP stampato e la porta TCP 8443. |
| `bridge_connect_qr` non legge l'immagine | `image_path` deve essere un percorso assoluto a un file locale regolare sul PC dell'agente, non sul PC remoto e non un URL. Un allegato in chat va prima salvato dove il processo MCP può leggerlo. Sono accettati PNG/JPEG statici identificati dalla firma, fino a 8 MiB compressi, 8192 pixel per lato e 16.777.216 pixel. Ritaglia l'immagine se contiene più inviti diversi; se il QR è troppo piccolo o sfocato usa **Salva PNG...** oppure **Copia invito**. |
| `bridge_request_access` fallisce o non compare una richiesta | Sul PC Windows apri la finestra QR (doppio clic o `host --qr`) e attiva **Ricevi richieste di accesso**. Senza UI la modalità non è disponibile. Verifica IP concreto, porta e raggiungibilità. Le richieste durano al massimo 120 secondi; il bridge ammette quattro pendenti, dieci nuove richieste al minuto complessive e tre per IP. |
| Il codice di confronto non corrisponde | Non approvare. Rifiuta la richiesta sul PC Windows e avviane una nuova. Confronta il codice mostrato dall'agente con quello nella finestra, controllando anche l'IP sorgente osservato e i privilegi; `client_label` è solo un nome dichiarato. Non trascrivere password Windows. |
| `bridge_access_status` resta `pending` | `pending` è normale prima dell'approvazione. Usa il `request_id` restituito da `bridge_request_access`, attendi almeno `poll_after_secs` (due secondi) tra i controlli e, se utile, imposta `wait_secs` fra 0 e 25. Il riavvio del client MCP perde le richieste in memoria: crea una nuova richiesta. Rifiuto, disattivazione della ricezione e scadenza non connettono il client. |
| I nuovi strumenti non appaiono o l'EXE non si aggiorna | Aggiorna entrambi i PC alla 0.6.0 e riavvia il client MCP per ricaricare `tools/list`. Su Windows un processo MCP ancora in esecuzione può impedire la sovrascrittura dell'EXE: arrestalo prima di copiare la nuova build. |
| Il PC controllato non è raggiungibile | La selezione automatica segue la route IPv4 predefinita: VPN e più schede possono produrre un IP diverso dalla LAN desiderata. Usa host --bind IP_LAN da un terminale elevato. La regola firewall automatica vale per Private e LocalSubnet, non per Public; verifica il profilo di rete, la policy aziendale e la raggiungibilità tra i due PC. |
| La finestra UAC o l'avvio del bridge fallisce | Approva UAC **sul PC controllato**. L'avvio standard richiede l'elevazione per PowerShell e la regola firewall. Se una policy blocca la regola, verifica la policy locale con l'amministratore della macchina. |
| windows_info funziona ma screenshot o click no | Serve una sessione desktop **interattiva, visibile e sbloccata**. Sessione 0, blocco schermo e desktop protetto UAC non sono utilizzabili. In una prova con RDP minimizzato, desktop_screenshot ha restituito GDI StretchBlt error 5: lascia visibile la finestra RDP e riprova. Un sent_inputs positivo conferma l'invio degli eventi, non l'effetto nell'app; controlla il nuovo screenshot e il focus. |
| L'agente clicca nel punto sbagliato | desktop_click usa pixel fisici del desktop virtuale; lo screenshot può essere ridotto e avere origine negativa con più monitor. Usa dimensioni e origine restituite da desktop_screenshot per convertire le coordinate; poi acquisisci un nuovo screenshot. |
| Upload o download fallisce | Entrambi i percorsi devono essere assoluti. local_path è sul PC dell'agente, remote_path sul PC controllato. La cartella di destinazione deve esistere: creala prima, eventualmente con directory_create e recursive: true sul remoto. La sostituzione è disattivata per default (overwrite: false). Il limite è 10 GiB per file. |
| Un comando PowerShell va in timeout o un'app avviata si chiude | powershell_execute esegue un processo nuovo per chiamata, con timeout massimo di **120 secondi**. Alla fine del comando o al timeout termina i processi discendenti; l'avvio di una GUI con Start-Process non garantisce che resti aperta. Usa l'input desktop per interagire con una GUI già nella sessione visibile e verifica l'esito sul PC controllato. |

La connessione salvata sul PC dell'agente contiene credenziali temporanee: trattala come file privato. `bridge_connect`, `bridge_connect_qr` e l'accesso approvato sostituiscono la connessione solo dopo la verifica del nuovo host; il comando manuale `pair` non sovrascrive un file esistente. Spegnere **Ricevi richieste di accesso** elimina le richieste in attesa, ma non revoca i client già connessi: condividono il bearer della sessione. Per revocarli tutti arresta il bridge o attendi la scadenza; la revoca selettiva non è disponibile. Se il bridge è scaduto, riavvialo sul PC controllato. Per limiti e argomenti completi consulta il [README](../README.md).

La release 0.5.0 richiede Windows moderno. L'errore di avvio `SetThreadDpiAwarenessContext / Entry Point Not Found` su Server 2012 R2 deriva da un import diretto dell'API: usa la build Windows 7 della 0.5.1. Sui sistemi legacy screenshot e input sono disabilitati e `windows_info` ne spiega il motivo; comandi e file restano le capacità previste. Vedi [compatibilità](compatibility.md).
